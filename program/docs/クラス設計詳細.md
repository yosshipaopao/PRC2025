# クラス設計詳細ドキュメント

## 1. クラス階層と役割

プログラム全体は 7 つの主要クラスで構成される：

- **Motor**: DC モーターの方向と速度を制御（×4 個）
- **Sensor**: 赤外線センサーの入力を統合管理
- **MotorPowerAverager**: モータへの速度指令をスムージング処理
- **StateManager**: センサー状態を分類・遷移追跡
- **TimeoutManager**: イベントの再発動を防止
- **Debug**: シリアル出力によるデバッグ機能
- **DFRobotDFPlayerMini**: 外部 MP3 ライブラリ（ロボット動作時に必要に応じて使用）

各クラスは単一の責任を持ち、他のクラスと協力してロボット制御システムを実現する。

## 2. メソッド動作の説明

### 2.1 Motor::run() メソッド

モーターの速度を指定する。内部では速度値に応じて以下の処理を自動選択：

- **正の値（前進）**: 左ピンを HIGH、右ピンを LOW に設定し、PWM ピンで速度制御
- **負の値（後進）**: 左ピンを LOW、右ピンを HIGH に設定（反転）し、速度制御
- **ゼロ（停止）**: 両ピンを LOW に設定して完全停止
- **範囲制約**: 入力値を -255～+255 に制約して、PWM の有効範囲を保証

### 2.2 Sensor::read() と state() メソッド

Sensor クラスは読み込みと状態生成を分離：

- **read()**: 全センサーのアナログ値を取得し、内部キャッシュに保存。毎ループで呼び出される
- **state()**: キャッシュ内の値を閾値と比較し、黒/白を判定。結果を 6ビットの値に変換

このように分離することで、state() を複数回呼び出しても、最新の読み込み値が使われる。

### 2.3 MotorPowerAverager の動作原理

バッファに速度値が溜まるにつれて、加重平均で出力を計算：

最新の値ほど高い重みを付けることで、即座に反応しながらも振動を防ぐ。例えば指令が 130 から 70 に変わった場合、バッファが徐々に埋まるにつれて 126 → 124 → 122 → ... → 70 と滑らかに遷移する。

### 2.4 StateManager::updateState() メソッド

新しいセンサー状態が入力されるたびに、以下の判定を実施：

1. センサー値をテーブルで グループに変換
2. 新グループが前フレームと同じなら、カウンタをインクリメント
3. 異なるなら、カウンタが 5 を超えていれば状態を確定し、イベント信号を返す
4. カウンタが 5 未満なら、無視してカウンタをリセット

つまり同じ状態が 5フレーム（約 25ms）以上続かないと、真の状態遷移として認識されない。

### 2.5 TimeoutManager::set() と get() メソッド

set() で「現在時刻 + 指定時間」をタイムアウト時刻として記録。get() で現在時刻がそれを超えたかを判定（オーバーフロー対応で差分計算）。

このシンプルな仕組みで、最大 16 個の独立したタイムアウトを管理できる。
  │   ├─ left_sum, right_sum: 8 bytes
  │   └─ 合計: 432 bytes
  ├─ StateManager インスタンス: 24 bytes
  ├─ TimeoutManager インスタンス: 80 bytes
  │   (timeout_times[16] + is_set[16])
  ├─ state_map[]: 136 bytes (17 entries)
  ├─ その他グローバル変数: 20 bytes
  └─ 合計: ~1600 bytes (利用可能メモリの < 1%)
```

## 7. 実行時パフォーマンス特性

### 7.1 メインループの実行時間内訳

```
┌─────────────────────────────────────────┐
│      5ms メインループ周期               │
├─────────────────────────────────────────┤
│ sensor.read()              : < 0.5 ms   │
│   └─ 6回の analogRead()                 │
│                                         │
│ state_manager.updateState(): < 0.5 ms   │
│   └─ mapState() テーブル探索            │
│                                         │
│ イベント検出ロジック         : < 0.5 ms │
│   └─ if 文の条件判定                    │
│                                         │
│ ライントレーサー制御         : < 0.5 ms │
│   └─ switch-case によるマッピング       │
│                                         │
│ run_motor() / stop_motor()   : < 0.5 ms │
│   └─ motorPowerAverager.addPower()     │
│                                         │
│ _run_motor()                : < 1 ms    │
│   └─ 4×Motor::run() → digitalWrite()   │
│       + analogWrite()                   │
│                                         │
│ その他（yield, 時間計測）  : < 0.5 ms  │
├─────────────────────────────────────────┤
│ 合計実行時間               : < 3.5 ms   │
│ 余裕時間                   : > 1.5 ms   │
└─────────────────────────────────────────┘
```

### 7.2 C字折り返し検出時の遅延

```
状態遷移確定: 5フレーム × 5ms = 25ms
イベント処理: 2000ms (delay)
復帰時間: 5000ms (timeout)

合計ブロック時間: 最大 7000ms = 7秒
```

## 8. エラーハンドリング

### 8.1 現在のエラー処理

```cpp
// Motor::run() での速度制約
speed = constrain(speed, -255, 255);  // オーバーフロー防止

// TimeoutManager での ID チェック
if (id < 0 || id >= MAX_TIMEOUTS) return;  // 範囲外チェック

// StateManager での未登録状態
if (mapped_current == -1)
  mapped_current = state;  // 前の状態を維持
```

### 8.2 改善提案

| 問題 | 現在 | 改善案 |
|------|------|--------|
| オーバーフロー対応 | (long) キャスト | unsigned long 使用 |
| メモリリーク | delete[] で解放 | スマートポインタ使用 |
| スタックオーバーフロー | 静的配列 | リングバッファ |
