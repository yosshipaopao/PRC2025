# ロボット動作ガイドと実行フロー

## 1. ロボットの役割と目的

本ロボットは以下の機能を持つ **自動ライントレーサー** である：

1. **黒線追従**: 床に引かれた黒線（赤外線センサーで検出可能）を自動で追従
2. **特殊地点の認識**:
   - **C字折り返し地点**: 左旋回して進行方向を変更
   - **十字交差点**: 十字路を横断
   - **行き止まり検出**: ライン喪失時に回転して復帰

---

## 2. コース構成と想定シーン

### 2.1 想定するコースレイアウト

```
            ┌─────────────┐
            │   スタート  │
            │    地点     │
            └──┬──────────┘
               │ 黒線
               │
         ┌─────┘
         │
         │  直進
         │
         ├───────────────┬─────────→ 十字交差点A
         │               │
         │      左への    │
         │      C字折り   │
         │      返し地点  │
         │               │
         └───────────────┘
               ↑
               │ 直進（復帰）
               │
         ┌─────┴─────────┐
         │  行き止まり   │  ← C字復帰地点（ライン喪失）
         │   (壁 or 落差) │
         └───────────────┘
```

### 2.2 コース内のセンサー状態変化

ロボットが黒線を追従しながら、コース上のセンサー状態が変化する例：

**通常直進**: 複数センサーで黒線を同時検出（中央グループ）→ 前進継続

**左寄り検出**: 左側センサーが反応し始める → 段階的に左への舵切り実行

**C字折り返し地点**: 長時間左寄り状態 → 急に中央またはラインなしに変化 → **C字検出イベント発火** → 左旋回コマンド実行

**十字交差点**: 一時的にすべてのセンサーが黒を検出 → その後中央線に戻る → **十字検出イベント発火** → カウンタ増加（走行継続）

**行き止まり**: ラインが完全に喪失（全センサー白） → 長時間続く → **復帰検出イベント発火** → 右旋回コマンド実行

各状態遷移は、状態継続フレーム数のカウンタ管理により、ノイズで一瞬変化しても無視される安全設計。

## 3. タイムラインと状態遷移

### 3.1 起動から通常走行までの流れ

**0～2秒**: setup() 関数で全ハードウェアを初期化（モーター、センサー、状態マップなど）

**2秒**: loop() 開始。メインループが 5ms 周期で無限実行

**2～2.3秒**: 最初のセンサー読み込みで初期状態を検出

**2.3～2.4秒**: 状態マップで グループに変換し、5フレーム以上の継続で初期グループを確定

**2.5秒以降**: ライントレーサー制御が開始。以下のサイクルが繰り返される：
1. センサーから6つのアナログ値を取得
2. 状態管理で グループと遷移を判定
3. 検出されたグループに応じて左右モーター速度を決定
4. 電力平均化器でスムージング後、モーターを駆動
5. 5ms 待機 → 次のループへ

このサイクルが継続する限り、ロボットは黒線を自動追従する。
         └─ モーター制御
```

### 3.2 C字折り返し地点での詳細フロー

```
フレーム   センサー     グループ  state_count  イベント
────────────────────────────────────────────────────────────
n-10    0b110000  → 1        9         -
n-9     0b110000  → 1        10        -
n-8     0b111000  → 1        11        -
n-7     0b111100  → 1        12        -
n-6     0b111110  → 1        13        -
n-5     0b011000  → 1        14        -
n-4     0b001100  → 1        15        -
n-3     0b000110  → 1        16        -
### 3.2 C字折り返し地点での処理フロー

**検出条件**: 左寄り状態（Group 1）が 10フレーム以上続いた後、急に中央またはラインなし状態（Group 0 or -1）に変化

**検出時刻**: 状態遷移の瞬間（フレーム n のときに prev_state=1, current_state=0 となる瞬間）

**検出後の動作**:
1. motorPowerAverager で左モーターを 0、右モーターを 130 で満たす（50フレーム分）
2. _run_motor() で実際のモーターを駆動（左停止、右全速）
3. ロボット は右中心で左回転開始
4. delay(2000) で 2秒間回転を続行
5. timeout_manager.set(0, 5000) で 5秒のタイムアウトを設定
6. 以降 5秒間は同じイベントの再検出を無視

**復帰タイミング**: 回転完了後、センサーが新しい黒線方向を検出してグループが変わり、5秒経過後は同じイベントを再度検出可能

---

### 3.3 十字交差点での処理フロー

**検出条件**: 全センサー検出状態（Group 4）が 10フレーム以上続いた後、中央またはラインなす状態（Group 0 or -1）に変化

**検出後の動作**:
1. timeout_manager.set(3, 3000) で 3秒のタイムアウトを設定
2. cross_count をインクリメント（交差点の通過回数をカウント）
3. モーター制御は通常通り継続（特に変更なし、そのまま直進）

**機能**: 十字交差点を横断したことを記録するための単純なイベント。モーター動作の変更は伴わない。

---

### 3.4 行き止まり（C字復帰）での処理フロー

**検出条件**: ラインなし状態（Group 3）が 100フレーム以上（約 500ms）継続

**検出後の動作**:
1. motorPowerAverager で左モーターを -130、右モーターを 130 で満たす
2. _run_motor() で実際のモーターを駆動（左後進、右前進）
3. ロボット は左中心で右方向に回転開始
4. delay(2000) で 2秒間回転
5. timeout_manager.set(1, 5000) で 5秒のタイムアウトを設定
6. 回転中にセンサーが黒線を再検出したら、新しいグループに遷移して通常走行に復帰

**特徴**: C字検出と異なり、モーター速度の向きが反対（左後進）で、右方向への回転で行き止まりから脱出する。
                    └──────────┬───────────┘
                               │
                     ┌─────────▼──────────┐
                     │  Group 0 (中央)    │ ← ほとんどの時間
                     │  前進 (130, 130)   │
                     └──┬───────────┬─────┘
                        │           │
         ┌──────────────┘           └──────────────┐
         │                                         │
    ┌────▼──────────┐                      ┌──────▼────────┐
    │ Group 1 (左)  │                      │ Group 2 (右)  │
    │ 右に舵切り     │                      │ 左に舵切り     │
    │ 左速度 < 右    │                      │ 左速度 > 右    │
    └────┬──────────┘                      └───┬───────────┘
         │  ← C字折り返し検出 ─────────────→ │
         │  (state_count >= 10,              │
         │   遷移先が Group 0 or -1)         │
         │                                  │
         │  [アクション]                     │
         │  左停止、右全速前進               │
         │  delay(2000)                     │
         │  timeout_manager.set(0, 5000)    │
         │                                  │
         ├─────────────────────────────────┤
         │                                 │
    ┌────▼─────────────┐          ┌───────▼──────┐
    │  Group 4 (全)    │          │ Group 3 (無) │
    │  十字交差点中     │          │ ライン喪失   │
    └────┬──────────────┘          └───┬──────────┘
         │                             │
         │ ← 十字交差点検出 ──────────┤
         │   (state_count >= 10,       │
         │    遷移先が Group 0 or -1) │
         │                             │
         │ [アクション]                │
         │ cross_count++               │
         │ timeout_manager.set(3, 3000)│
         │                             │
         └────────────┬────────────────┘
                      │
                      │ ← C字復帰検出
                      │   (state_count >= 100,
                      │    遷移元/先に関わらず Group 3)
                      │
                      │ [アクション]
                      │ 左後進、右前進
                      │ delay(2000)
                      │ timeout_manager.set(1, 5000)
                      │
                      └──→ Group 0 へ復帰
                          通常走行再開

凡例:
Group 0: 中央（直進）- 正常時
Group 1: 左寄り - 左に舵切り中
Group 2: 右寄り - 右に舵切り中
Group 3: ラインなし - 行き止まり
Group 4: 全センサー - 十字交差点
-1: 未登録状態 - 前の状態を維持
```

## 5. モーター速度テーブルの詳細

### 5.1 ラインの位置と走行方向

```
センサー配置（一例）:
  左 ◌ ◌ | ◌ ◌ 右
  pin[4] pin[3] pin[2] pin[1] pin[0]
                |
              中央

センサー値の解釈:
  
  ◌ | ◌        → 0b11100 (左寄り, Group 1)
  ◌ | ◌ ◌      → 0b11110 (左寄り, Group 1)
    | ◌        → 0b00100 (中央, Group 0)
  ◌ | ◌        → 0b01110 (中央, Group 0)
  ◌ ◌ |        → 0b00111 (右寄り, Group 2)
```

### 5.2 モーター速度マッピング

```
左旋回:
  0b10000 (pin[4] のみ黒)  → run_motor(-130, 130)
  │ 左後進 │ 右前進
  └─ ロボット は左中心で右方向に回転

右旋回:
  0b00001 (pin[0] のみ黒)  → run_motor(130, -130)
  │ 左前進 │ 右後進
  └─ ロボット は右中心で左方向に回転

左に軽く舵切り:
  0b01100, 0b11100        → run_motor(70, 130)
  │ 左減速 │ 右通常速
  └─ ロボット は前進しながら右に回転

右に軽く舵切り:
  0b00110, 0b00111        → run_motor(130, 70)
  │ 左通常速 │ 右減速
  └─ ロボット は前進しながら左に回転

左に強く舵切り:
  0b01000, 0b11000        → run_motor(0, 130)
  │ 左停止 │ 右通常速
  └─ ロボット は ほぼ その場で右に回転

右に強く舵切り:
  0b00010, 0b00011        → run_motor(130, 0)
  │ 左通常速 │ 右停止
  └─ ロボット は ほぼ その場で左に回転
```

## 6. タイムアウト管理の実装パターン

### 6.1 なぜタイムアウトが必要か

```
C字折り返しを検出した直後、ロボットは左回転を始める。
この際のセンサー状態も一時的に Group 1（左寄り）になり、
その後 Group 0（中央）に戻る。

もしタイムアウトがなければ：
  T0:    C字検出 (Group 1 → Group 0)
  
  T1:    回転中... センサー状態が左寄り (Group 1) に
         → またも Group 1 → Group 0 状態遷移検出！
         → またも C字検出！
         → 無限ループ...
```

### 6.2 タイムアウトによる保護

```
T0:    C字検出 (Group 1 → Group 0)
       └─ timeout_manager.set(0, 5000)
       
T0~T400: 回転中...
         新しい検出は timeout_manager.get(0) = true
         → 保護中なので イベント検出条件不成立
         
         if (... && timeout_manager.get(0) == false)
            ↑ ここが false なので処理スキップ
         
T401:  5秒経過
       timeout_manager.get(0) = false
       → 保護解除
       
       以降は またも C字が検出できる状態に
```

## 7. ライントレーサー精度の調整

### 7.1 スムージング効果（MotorPowerAverager）

```
急激な速度変更なし（加重平均による段階的変更）:

通常:
  速度指令: 130 → 70 → 130 → 70 (急激な変更)
  モーター: そのまま適用 → 不安定

スムージング後:
  速度指令: 130 → 70 → 130 → 70
  バッファ: [130, 130, 130, 130, 130, 130, 130, 130,
             130, 130, 130, 70, 70, 70, ...]
  加重平均: 126 → 124 → 122 → 120 → ... → 70 (なめらか)
  モーター: 段階的に減速 → 安定走行
```

### 7.2 精度調整パラメータ

| 項目 | 現在値 | 調整の考え方 |
|------|--------|-----------|
| RUN_SP | 130 | 増加: 速走行（不安定になる可能性） / 減少: 低速走行（ゆっくり） |
| HALF_STOP_SP | 70 | 増加: 舵切りが弱くなる / 減少: 舵切りが強くなる |
| バッファサイズ | 50 | 増加: よりスムーズ（応答遅延増加） / 減少: 応答速い（ガタつき増加） |
| C_detection_threshold | 10 | 増加: 誤検出が減る（検出遅延） / 減少: 反応が速い（誤検出増加） |
| センサー閾値 | 2000 | 増加: 暗い環境対応 / 減少: 明るい環境対応 |

## 8. デバッグの方法

### 8.1 デバッグ出力の有効化

`platformio.ini` または `platformio.local.ini` で設定:

```cpp
// src/debug.h の先頭で
#define DEBUG_ENABLED 1  // 1 = 有効、0 = 無効
```

再コンパイル & アップロード

### 8.2 モニタでの確認

シリアルモニターを開く（115200 baud）:

```
Starting...
State changed: -1 -> 0 | Count: 0
State changed: 0 -> 1 | Count: 12
C detected! State count: 12
State changed: 1 -> 0 | Count: 16
State changed: 0 -> 1 | Count: 8
...
```

### 8.3 状態値の読み方

```
0b00100  → pin[2] のみ黒 → 中央センサー
0b11111  → 全センサー黒 → 十字交差点
0b110000 → pin[4], pin[5] 黒 → 左寄り（最も左）
```

## 9. 想定される問題と対応

### 9.1 ロボットが黒線を追従しない

```
原因: センサー閾値が不適切
確認方法:
  1. デバッグを有効化
  2. sensor.print_raw() で生値を確認
  3. 黒い場所で値が上がる、白い場所で値が下がることを確認
  
対応:
  const int threshold = 2000;  ← これを調整
  
  明るい環境: threshold を上げる (例: 2500)
  暗い環境: threshold を下げる (例: 1500)
```

### 9.2 モータが片方だけ動く

```
原因: ハードウェア接続ミス または ピン番号の設定ミス
確認方法:
  1. モーター配線を確認
  2. ピン番号が間違っていないか確認
  
  M1: left=37, right=38, pwm=39
  M2: left=21, right=26, pwm=33
  M3: left=35, right=36, pwm=34
  M4: left=20, right=19, pwm=18
```

### 9.3 C字折り返しが検出されない

```
原因: 左寄りセンサーの感度が低い
確認方法:
  1. デバッグで状態遷移を監視
  2. Group 1（左寄り）に遷移しているか確認
  
対応:
  const int C_detection_threshold = 10;  ← これを調整
  
  あまり検出されない: 値を減らす (例: 5)
  誤検出が多い: 値を増やす (例: 15)
```
