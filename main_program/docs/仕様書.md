# PRC2025 メインプログラム 仕様書

**作成日**: 2026年1月28日  
**プロジェクト名**: PRC2025 Main Program  
**対象プラットフォーム**: ESP32S2 (PlatformIO)  
**プログラム言語**: C++

---

## 1. 概要

本プログラムは、ロボットカー（4輪駆動）を制御するメインプログラムである。複数のセンサーからの入力に基づいてライントレーサー機能を実装し、複雑な経路（特にコースの折り返し地点を検出）を自動で走行する。

### 主な機能
- **ライントレーサー**: 6つのセンサーからの入力に基づいて、ロボットが黒線を追従
- **コース検出**: 「C字折り返し地点」や「十字交差点」を検出し、特殊な動作を実行
- **モータ制御**: 4つの DC モーターを PWM で制御
- **音声出力**: MP3 ファイルを再生可能（DFPlayer Mini）
- **デバッグ機能**: 条件付きデバッグ出力機能

---

## 2. ハードウェア仕様

### 2.1 マイコン
- **ボード**: ESP32 Development Kit (board_build.mcu: esp32s2)
- **フレームワーク**: Arduino
- **モニター速度**: 115200 baud

### 2.2 モーター設定

4つの DC モーターを2グループに分けて制御:

#### グループ1（左側）
| モーター | Left Pin | Right Pin | PWM Pin |
|---------|----------|-----------|---------|
| M1      | 37       | 38        | 39      |
| M2      | 21       | 26        | 33      |

#### グループ2（右側）
| モーター | Left Pin | Right Pin | PWM Pin |
|---------|----------|-----------|---------|
| M3      | 35       | 36        | 34      |
| M4      | 20       | 19        | 18      |

### 2.3 センサー設定

**赤外線ラインセンサー**: 6個  
**センサー入力ピン**: [13, 14, 15, 16, 17, 12]  
**閾値**: 2000 (2000以上でセンサーが黒線を検出)  

センサー状態はビットマップで表現される:
```
状態値 = ビット0:pin[0], ビット1:pin[1], ... ビット5:pin[5]
ビットが1 = 黒線検出, ビットが0 = 白地検出
```

### 2.4 その他のハードウェア
- **LED**: ピン6 (デジタル出力)
- **MP3プレーヤー**: DFRobotDFPlayerMini (UART1経由)

## 3. ソフトウェアアーキテクチャ

### 3.1 クラス構成

```
┌─────────────────────────────────────────┐
│         Main Program (main.cpp)         │
├─────────────────────────────────────────┤
│ ├─ Motor x4                             │
│ ├─ MotorPowerAverager                   │
│ ├─ Sensor                               │
│ ├─ StateManager                         │
│ ├─ TimeoutManager                       │
│ └─ DFRobotDFPlayerMini                  │
└─────────────────────────────────────────┘
```

### 3.2 各クラスの概要

#### **Motor クラス** (`motor.h`)
DC モーターの制御を担当。各モーターは左回転・右回転・PWM制御の3つのピンを持つ。

**機能**:
- **初期化**: ピンを出力モードに設定
- **速度制御**: -255 ～ +255 の範囲で速度と方向を指定
  - 正の値で前進（左右ピンで HIGH/LOW を制御）
  - 負の値で後進（ピン制御を逆転）
  - ゼロで停止（両ピンを LOW）
- **PWM**: アナログ出力で モーターの速度を 0～255 段階で制御

#### **Sensor クラス** (`sensor.h`)
赤外線ラインセンサーの読み込みと状態判定を担当。複数のセンサーからの値をまとめて管理し、黒線検出状態をビットマップで表現する。

**機能**:
- **初期化**: 6つのセンサーピンを入力モードに設定
- **値の読込**: 定期的にすべてのセンサーから アナログ値（0～4095）を取得
- **黒判定**: 閾値 2000 以上なら黒線と判定
- **状態生成**: 複数センサーの黒/白結果を 6ビットの値に変換（ビット i が 1 = センサー i で黒検出）
- **デバッグ出力**: センサーの生値またはビット状態をシリアルで出力

#### **Motor Power Averager クラス** (`motor_power_averager.h`)
モータの速度指令に加重移動平均を適用し、スムーズな加速を実現。急激な速度変更を避けることで、ロボットが安定走行する。

**機能**:
- **バッファリング**: 最大 50 フレーム分の左右速度を保持
- **加重平均化**: 最新のデータほど高い重みを付けて平均化（新しい指令をより重視しつつ緩和）
- **段階的制御**: 単なる平均ではなく加重により、タイムリーな反応と滑らかさを両立
- **強制設定**: C字折り返し検出時など、即座にバッファ全体を指定値で埋める機能

#### **State Manager クラス** (`state_manager.h`)
センサーの 6 ビット状態値を 5 つのグループに分類し、状態遷移を追跡する。ノイズ除去のため、同じ状態が 5 フレーム以上続かないと状態遷移と認識しない。

**機能**:
- **状態マッピング**: センサーの生ビット値をテーブルで グループ ID（0～4）に変換
- **状態確定**: 一時的なセンサーノイズを無視し、充分な継続時間で状態遷移を確定
- **イベント検出**: 前回の状態と現在の状態が異なるとき、また状態継続フレーム数が増えたときにイベント検出条件をチェック
- **柔軟な状態転移**: 未登録状態は前の状態を維持し、無意識の状態変化を防止

#### **Timeout Manager クラス** (`timeout_manager.h`)
イベントの再発動を防ぐため、指定時間の待機を最大 16 個まで並行管理する。例えば C字検出後、5秒間は同じイベントを無視する仕組みを提供。

**機能**:
- **タイムアウト設定**: ID ごとに「現在時刻 + 指定時間」を記録
- **経過判定**: 現在時刻がタイムアウト時刻に達したか判定
- **複数管理**: ID 0～15 の異なるイベントを独立管理
- **オーバーフロー対応**: マイコンの時間カウンタが巻き回ってもカウンタの差分で正確に比較

## 4. 状態管理

### 4.1 状態マップテーブル

センサーの6ビット値は以下のグループに分類される:

| Group ID | 説明 | センサー状態例 |
|----------|------|---|
| 0 | **中央（直進）** | 0b00100, 0b01110, 0b01010, 0b01100, 0b00110, 0b11110, 0b01101, 0b10110 |
| 1 | **左寄り** | 0b110000, 0b111000, 0b111100, 0b111110 |
| 2 | **右寄り** | 0b00111, 0b01111 |
| 3 | **ラインなし** | 0b00000 |
| 4 | **全センサー** | 0b11111, 0b111111 |

### 4.2 状態遷移

```
状態遷移は以下の条件で確定する:
- 同じマップ状態が5フレーム以上連続
- 前の状態がcountフレーム以上で初めて確定
```

## 5. 制御ロジック（メインループ）

### 5.1 ループ間隔
- **LOOP_INTERVAL**: 5 ms
- ループ周期が 100 ms 以上遅延した場合は同期をリセット

### 5.2 実行順序

メインループは 5ms ごとに実行され、以下の順序で処理が進む：

1. **ウォッチドッグリセット**: マイコンの監視タイマーを最初化
2. **実行タイミング同期**: 次のループ実行時刻まで待機（5ms 周期）
3. **センサー読み込み**: 6個のセンサーから最新のアナログ値を取得
4. **状態管理と検出**: 
   - センサー値から 6ビット状態を生成
   - StateManager で状態遷移を確定
   - C字折り返し、十字交差点、行き止まり復帰の各イベント検出
5. **ライントレーサー制御**: センサー状態に応じてモーター速度を決定
6. **モータ実行**: 速度指令をスムージング後、実際にモーターを駆動

### 5.3 イベント検出ロジック

#### **C字折り返し検出** (Group 1 → Group 0 or -1)

ロボットが左側に長時間寄り続けたあと、急に中央またはライン喪失の状態になった場合、左旋回コマンドが発火する。

**条件**:
- 前フレームの状態: Group 1（左寄り）
- 現フレームの状態: Group 0（中央）または -1（未登録）
- 前フレームの状態継続: 10フレーム以上（約 50ms）
- タイムアウト0が無効: 5秒以内の重複検出を防ぐ

**実行動作**: 
ロボットの左モーターを停止、右モーターを全速で駆動し、2秒間左旋回を実行。その後 5秒間のタイムアウトを設定して同じイベントの連続検出を防止。

---

#### **十字交差点検出** (Group 4 → Group 0 or -1)

すべてのセンサーが黒線を検出した状態（十字路中央）から、中央線に戻る状態への遷移で検出。

**条件**:
- 前フレームの状態: Group 4（全センサー検出）
- 現フレームの状態: Group 0（中央）または -1（未登録）
- 前フレームの状態継続: 10フレーム以上
- タイムアウト3が無効: 3秒以内の重複検出を防ぐ

**実行動作**: 
十字交差点カウンタを 1 増やし、3秒のタイムアウトを設定。モーター制御は通常通り直進を継続。

---

#### **C字復帰検出** (Group 3 が長時間継続)

ロボットが行き止まりに達してライン喪失状態が長く続く場合、復帰回転を実行。

**条件**:
- 現在の状態: Group 3（ラインなし）
- 状態継続時間: 100フレーム以上（約 500ms、閾値の 10 倍）
- タイムアウト1が無効
- タイムアウト0が無効（C字検出による回転中でない）

**実行動作**: 
ロボットの左モーターを後進、右モーターを前進で駆動し、2秒間右旋回を実行。その後 5秒間のタイムアウトを設定。

### 5.4 ライントレーサー制御

6ビットセンサー状態に応じて、左右モーターの速度を以下のテーブルで指定する。指定された速度は即座にはモーターに適用されず、MotorPowerAverager でスムージングされて段階的に変更される。

**制御ロジック**:
- **直進（速度 130, 130）**: 複数センサーが同時に黒線検出（中央付近）
- **左への軽い舵切り（速度 70, 130）**: 左側センサーが少し反応（左寄り開始）
  - 左速度を 130→70 に減速して左に曲がる
- **右への軽い舵切り（速度 130, 70）**: 右側センサーが少し反応（右寄り開始）
- **左への強い舵切り（速度 0, 130）**: 左側のみ反応（強い左寄り）
  - 左を停止して右全速 → ロボット はほぼその場で右に回転
- **右への強い舵切り（速度 130, 0）**: 右側のみ反応（強い右寄り）
- **左旋回（速度 -130, 130）**: 最左センサーのみ反応（急カーブ）
  - 左後進 + 右前進 → 左中心で右方向に回転
- **右旋回（速度 130, -130）**: 最右センサーのみ反応（急カーブ）
  - 左前進 + 右後進 → 右中心で左方向に回転
- **無操作**: ラインなし（0b00000） → 前回の速度を維持

センサー状態ごとの詳細マッピングは、仕様書前半の状態グループ表を参照。

## 10. 初期化フロー (setup 関数)

プログラム開始時、以下の順序でハードウェアとソフトウェアが初期化される：

1. **2秒待機**: マイコンの電源供給が安定化するまで待機
2. **デバッグシリアル初期化**: デバッグ機能が有効な場合、シリアル通信を初期化（115200 baud）
3. **LED ピン設定**: GPIO6 を出力モードに設定
4. **モーター初期化**: M1～M4 の 3ピンずつ（計 12ピン）を出力モードに設定
5. **センサー初期化**: 6個のセンサーピンを入力モードに設定
6. **状態マップ設定**: StateManager にセンサー状態からグループへの変換テーブルを登録
7. **メインループ基準時刻記録**: 最初のメインループ周期を正確に計測するため現在時刻を記録

## 11. 状態遷移図

センサーの 6ビット値は以下の流れで処理され、イベント検出に至る：

1. **センサー入力**: GPIO 13～17, 12 から読み込まれたアナログ値が 2000以上なら該当ビットを 1 にセット（例：0b110011）
2. **状態マッピング**: StateMapEntry テーブルで検索し、グループ ID（0～4）に変換。未登録なら -1 を返す
3. **状態確定**: 新しいグループが 5フレーム以上続いたら、前フレームの状態を確定
4. **イベント検出**: 確定した状態遷移と状態継続フレーム数によって、C字検出、十字検出、復帰検出などのイベント条件をチェック

このように段階的に処理することで、ノイズによる誤検出を防ぎながら、確実にコース上の特殊地点を認識できる。

---

## 12. タイムアウト管理の詳細

**目的**: 同じイベントの連続トリガーを防止

| Timeout ID | イベント | 時間 |
|-----------|---------|------|
| 0 | C字折り返し検出 | 5000 ms |
| 1 | C字復帰検出 | 5000 ms |
| 3 | 十字交差点検出 | 3000 ms |

タイムアウト中のイベント検出は無視される。

## 13. 制御フロー図

メインプログラムは以下の流れで動作する：

1. **電源オン → setup()**: ハードウェア初期化（モーター、センサー、状態マップなど）
2. **loop() 開始**: メインループが 5ms 周期で無限実行
3. **タイミング同期**: 次の 5ms タイミングまで待機
4. **入力読み込み**: センサーから 6つのアナログ値を取得
5. **状態・イベント処理**: 
   - 状態マップで グループに分類
   - 状態遷移と継続時間を追跡
   - C字、十字、復帰のイベント条件をチェック
6. **制御出力**: 現在のセンサー状態またはイベント検出に応じて、左右モーターの目標速度を決定
7. **スムージング**: 指定速度をモータ電力平均化器で段階的に適用
8. **ループ**: 次の 5ms サイクルへ

このサイクルが継続する限り、ロボットは黒線を追従し続け、特殊地点で自動的に動作を切り替える。

## 14. 性能とリソース

### 14.1 メモリ使用量
モータパワーアバーサーの 50フレームバッファが最大メモリ消費（約 400 bytes）。ESP32S2 の全メモリ容量に対して 1% 未満であり、十分な余裕がある。

### 14.2 実行時間
メインループ内の全処理は 5ms の制限時間内に完了（実際は 3.5ms 程度）。余裕時間により、突発的な処理の遅延やウォッチドッグタイマーのリセットに対応可能。

## 16. トラブルシューティング

| 問題 | 原因 | 解決方法 |
|------|------|---------|
| ロボットが黒線を追従しない | センサー閾値が不適切 | threshold 値を調整（platformio.ini でコンパイル時に変更） |
| モーターが片方だけ動く | ピン設定ミス | M1～M4 のピン番号を確認 |
| 状態遷移が頻繁に発生 | センサー出力がノイズ | 状態継続フレーム数を増やす |
| イベント検出が連続で発動 | タイムアウト時間不足 | timeout_manager.set() の時間を延長 |
| ロボットが不安定に走行 | 電池電圧低下 | 電池交換またはスピード定数を低減 |
